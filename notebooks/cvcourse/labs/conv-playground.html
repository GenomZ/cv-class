Try this - predict first, then check

  1. Pick sobel x. Which edges will light up: the vertical ones (shoulders, sides of the face) or the horizontal ones? Now switch to sobel y.
    why

    Sobel x subtracts the left column from the right column, so it is large where brightness changes from left to right: vertical edges. Blue = dark-to-bright, red = bright-to-dark. Sobel y is the same kernel rotated.

  2. Hover a flat region (the background) with laplacian selected. What is the output, and why does it not depend on how bright the region is?
    why

    The weights sum to 0, so a constant patch gives c * 0 = 0. Any kernel that sums to zero ignores flat areas and responds only to change; a kernel that sums to 1 (blur, sharpen) keeps the overall brightness.

  3. Type a kernel that shifts the image one pixel to the right. (Start from identity.)
    answer

    Put the single 1 in the middle-left cell. out[i, j] then copies x[i, j-1]: every output pixel takes the value of its left neighbour, so the content moves right.

  4. Before clicking: with padding 0 and stride 2, how large is the output of this 64 px image? Check with the formula box.
    answer

    floor((64 + 0 - 3) / 2) + 1 = 31. Stride 2 keeps every second position, which is how convnets downsample.

  5. Set dilation to 3 with sobel x and hover the input. What happened to the taps, the parameter count, and the edges?
    why

    Still 9 weights, but spread over a 7x7 area (k_eff = 3 * (3 - 1) + 1). The receptive field grows for free, the edges get thicker, and with padding 1 the output shrinks because the effective kernel is larger.
