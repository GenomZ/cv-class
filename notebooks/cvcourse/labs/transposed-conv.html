Transposed convolution = scatter-add

D3-01 · section 4 All labs

A normal convolution gathers a window into one output pixel. A transposed convolution scatters: every input value is multiplied by the whole kernel and added into the output at a stride-spaced position. Step through it, hover an output pixel to see who painted it, and click input or kernel cells to change them.

Try this - predict first, then check

  1. Kernel 3, stride 2, all ones. Before pressing play: which output pixels will receive 4 stamps, which 2, which 1? Then hover them.
    why

    Stamps start every 2 pixels but are 3 wide, so they overlap by one row and one column. Pixels where two rows of stamps and two columns of stamps meet get 4, edges of a single overlap get 2, the rest 1. That periodic 1-2-4 pattern is the checkerboard: it is baked into every map this layer produces, before any learning.

  2. Keep stride 2 and try kernel 4, then kernel 2. Find the rule for when the count map is uniform.
    answer

    Uniform (away from the border) exactly when k is a multiple of s: k = 4 gives 4 everywhere, k = 2 gives 1 everywhere (the U-Net decoder's choice: no overlap at all). With k = 3, s = 2, or k = 4, s = 3, the overlap is uneven.

  3. Set kernel 3, stride 2, kernel bilinear, input all ones. The count map is still uneven; is the output? Now pick kernel random.
    why

    The bilinear weights (0.5, 1, 0.5) are chosen so the overlapping halves add up to 1: the interior of the output is flat although the counts are not. A learned kernel has no reason to keep that balance, so the pattern returns as soon as the weights are random. Uneven overlap makes artefacts likely; good weights can hide them, training rarely does.

  4. Input single 1, then stride 3 with kernel 2. What does one input pixel paint, and what happens between the stamps?
    why

    A single 1 paints exactly one copy of the kernel. With k < s the stamps do not touch: the zeros between them are output pixels no input ever reaches (count 0), the worst possible checkerboard.

  5. Switch the method to nearest + conv 3x3 (input all ones), then bilinear + conv 3x3. Compare with the transposed conv. Finally return to transposed, kernel 4, stride 2 and set padding 1: which pixels disappear, and what is the output size now?
    why

    Resize + conv: every output pixel sums exactly 9 taps of the upsampled map, so a constant input gives a flat interior (lower values only where the conv's zero padding enters). No pattern by construction. In a transposed conv, padding p crops p pixels from every side: (4 - 1) * 2 - 2 + 4 = 8 = 2n, the standard ConvTranspose2d(k=4, s=2, p=1) that exactly doubles.
