# Interactive labs: authoring guide

A lab is one self-contained HTML page that lets a student *manipulate* one mechanism and
watch the numbers move. Labs complement the notebooks: the notebook figure shows the
mechanism once, the lab lets you break it, and the exercise right after makes you write it.

```
labs/
  lab.css  lab.js        shared look + toolkit (global `Lab`), no dependencies, offline
  <name>.html            one lab each; conv-playground.html is the exemplar - read it first
  index.html             generated by tools/build_labs_index.py from the <meta> tags
  __init__.py            labs.show(name, **state) / labs.open(name) / labs.catalog()
tools/check_labs.py      headless smoke test + screenshots (-> labs/_shots/, git-ignored)
```

In a notebook (source in `tools/src/`):

```python
from cvcourse import labs        # in the setup cell
labs.show("iou-playground")      # last expression of its own code cell
```

`labs.show` inlines `lab.css` and `lab.js` and embeds the page in an iframe that resizes
itself, follows the JupyterLab / VS Code theme, and works in Colab. Keyword arguments
(and the URL hash, `page.html#stride=2&pad=0`) override the lab's initial state.

## The contract every lab follows

1. **One mechanism per lab**, named as the notebook names it, with the notebook's symbols
   (`k`, `s`, `p`, `IoU`, `gamma`, ...). The numbers a lab shows must equal what the course's
   Python reference (`cvcourse.convops`, `boxes`, `seg`, `torch`) gives for the same input.
2. **The first screen already teaches.** The default state shows an interesting case, not an
   empty canvas. Nothing important is hidden behind a click.
3. **Direct manipulation first.** Drag the box, paint the mask, click the cell. Sliders for
   genuine scalars (threshold, gamma, learning rate). Every change redraws immediately.
4. **Live numbers next to the picture**: `Lab.readout` tiles and a `.formula` box with the
   current values substituted into the formula from the notebook.
5. **A "Try this" list of 3-5 experiments**, phrased *predict first, then check*, each with a
   hidden `<details>` explanation. At least one exposes a failure mode or a misconception
   (IoU has no gradient for disjoint boxes; 97% pixel accuracy with an empty mask; ...).
6. **Required markup**: `<title>`, `<meta name="lab-notebook" content="D2-01">`,
   `<meta name="lab-summary" content="one sentence">`, `<meta name="lab-height" content="680">`
   (initial iframe height in px), exactly these two includes
   `<link rel="stylesheet" href="lab.css">` and `<script src="lab.js"></script>` (the loader
   replaces them verbatim), a `.lab` root with `.lab-head` (h1 + `.lab-tag` + `.lab-back`),
   `.lab-lede`, `.lab-stage`, `.try`.
7. **Self-contained**: no network, no external fonts / images / libraries. The only bundled
   image is `Lab.photo()`; draw everything else. Keep a lab under ~40 KB.
8. **Colour by role, from the CSS variables** (dark mode comes for free, never hard-code hex):

   | role | variable |
   |---|---|
   | ground truth | `--c3` |
   | prediction / the main series | `--c1` |
   | further series, in this fixed order | `--c2`, `--c4`, `--c5`, `--c6`, `--c7`, `--c8` |
   | the thing under the pointer / selected | `--hl` |
   | positive / kept / correct - negative / removed / wrong (always with a text label too) | `--good` / `--bad` |
   | ignored / inactive | `--muted` |
   | signed values (weights, gradients) | `Lab.divergingRGB(v)`: blue +, red - |
   | magnitudes (heat maps, counts) | `Lab.sequentialRGB(t)`; photos and activations `Lab.grayRGB(t)` |

   Text is always `--ink` / `--ink-2` / `--muted`, never a series colour. Two or more series
   need a `.legend`. Lines 2 px, markers >= 8 px, grid recessive (`Lab.axes` does this).
9. **Fits**: no horizontal scroll at 700 px width (the stage stacks below 760 px); at
   1000 px the whole lab including "Try this" should be at most ~900 px tall.
10. **State through `Lab.params`**: every control's initial value comes from
    `Lab.params({...})` so a notebook, a link or the smoke test can start the lab in any state.

## Toolkit (`lab.js`) in one screen

```js
const S = Lab.params({ thr: 0.5, mode: "iou" });        // defaults <- labs.show(...) <- URL hash
const c = Lab.canvas("#fig", 420, 300, { framed: true }); // c.ctx draws in 420 x 300 logical units (hi-DPI handled)
Lab.pointer(c, { down(p) {}, move(p) {}, up(p) {}, hover(p) {}, leave() {} });   // p = {x, y} in logical units
Lab.slider(parent, { label, min, max, step, value, fmt, onInput });  Lab.select(...);  Lab.segmented(...);
Lab.toggle(parent, { label, value, onChange });  Lab.button(parent, "Reset", fn);
const r = Lab.readout("#readouts", "IoU"); r.set("0.53");            // r.set("0.71", "good" | "bad")
const redraw = Lab.loop(draw);                                       // call redraw() from every handler
Lab.color("--c1")  Lab.alpha("--c1", 0.25)  Lab.divergingRGB(v)  Lab.sequentialRGB(t)  Lab.grayRGB(t)  Lab.inkOn(rgb)
Lab.text(ctx, "label", x, y, { size, weight, color, align, baseline, mono });
Lab.image(ctx, data, cols, rows, x, y, w, h, v => [r, g, b]);        // scalar field as pixels
Lab.cells(ctx, data, cols, rows, x, y, w, h, { color, fmt, highlight });   // small matrix with numbers
const ax = Lab.axes(ctx, { x, y, w, h, xmin, xmax, ymin, ymax, xlabel, ylabel });  ax.line(pts, color); ax.dot(x, y, color);
Lab.box(ctx, [x1, y1, x2, y2], { color, label, dash, fill });
Lab.photo().then(({ w, h, gray, rgb, img }) => ...);                  // 128 x 128 sample photo
Lab.rng(seed)  Lab.clamp  Lab.lerp  Lab.fmt(x, digits)  Lab.el(tag, props, ...children)  Lab.$(selector)
```

Known sharp edges of the toolkit:

* `--hl` is the same orange as `--c2`. A lab that needs a second series *and* a hover /
  selection highlight should mark the selection with shape (thicker outline, ring, dashes)
  rather than rely on the colour, or skip `--c2`.
* `Lab.sequentialRGB` runs light -> dark in the light theme and dark -> light in the dark
  theme (the low end always recedes into the surface). Never caption a heat map
  "dark = high"; draw a small colour key instead.
* `Lab.box` labels are white text: use it only with saturated series colours.
* `Lab.slider(...).set(v)` shows the step-rounded value.
* For automated interaction tests, expose a `window.labDebug()` that draws synchronously
  and returns the lab's state (see `seg-metrics.html`), then dispatch synthetic
  `PointerEvent`s from a wrapper page.

Need something the toolkit lacks? Write it inside your lab. Do not change `lab.js` /
`lab.css` in a way that alters existing labs.

## Checking a lab

```bash
python tools/check_labs.py iou                                   # load, fail on script errors, screenshot (light)
python tools/check_labs.py iou --theme dark --suffix=-t2 --state "thr=0.3&mode=giou" --width 700
python tools/build_labs_index.py                                 # refresh index.html
```

Look at the screenshots: light and dark, wide and 700 px, and at least two non-default
states. Compare every displayed number for one state with the Python reference.
Then open the page in a real browser and drag things.
