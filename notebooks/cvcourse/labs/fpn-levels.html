Try this - predict first, then check

  1. Set the object to 16 px and look at P5 (stride 32, the output stride of a plain ResNet). What fraction of one cell does it fill?
    why

    0.5 x 0.5 cells: a quarter of one cell, whose feature vector also describes 75% background. A single stride-32 grid (YOLOv1, the original DETR) has almost no signal for such objects. On P3 the same object covers 2 x 2 cells, and the FPN gives those cells the semantics of C5 through the top-down pathway.

  2. Predict the level for a 224 x 224 object under the RoI rule, then grow the object from 16 px to 512 px with the presets. Do the three rules agree?
    why

    The RoI rule sends a 224 px box to P4 by construction (k0 = 4 for the ImageNet size) and moves up one level per doubling. RetinaNet follows its anchor sizes (32 on P3 ... 512 on P7) and FCOS its distance ranges; near the boundaries they disagree by one level, and RetinaNet can make several levels positive at once.

  3. Make the box long and thin (e.g. 200 x 40 px). What happens to the best anchor IoU, and to FCOS?
    why

    RetinaNet's anchors only have aspect ratios 1:2, 1:1, 2:1, so the best IoU drops; when no anchor reaches 0.5, the matcher still forces the single best anchor to be positive (low-quality match), a weak target. FCOS does not care about the shape: it only compares max(l, t, r, b) with the level's range.

  4. With a 100 x 100 px object, count the FCOS points per level with and without centre sampling.
    why

    The centre point has max(l, t, r, b) = 50, inside P3's range (0, 64), but points away from the centre have larger distances and fall into P4's range (64, 128): one object, two levels. Without centre sampling most of P4's points inside the box become positive; centre sampling (radius 1.5 strides, torchvision's default) keeps only the ones near the centre, so the coarser level gets a few positives instead of dozens.

  5. Switch to the top-down pathway. Predict the shape of P3 for a 640 px input and d = 128, and where most FPN parameters sit. Then switch the backbone to ResNet-50.
    answer

    (1, 128, 80, 80). With ResNet-18 the three 3 x 3 smoothing convs hold most parameters (9 d2 each); with ResNet-50 only the 1 x 1 laterals grow (they read 512 / 1024 / 2048 channels), and at d = 128 they now outweigh the smoothing convs. The input size changes every shape and no parameter count: the same FPN runs on any image size.
